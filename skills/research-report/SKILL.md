# 研究与项目报告

根据真实材料完成适合目标读者的正式报告。保持内容可核验、文字自然、版式统一，交付前检查实际导出文件。本技能适用于不同研究和项目主题；示例中的资料与数字仅用于演示。

## 先判断本次任务

- 新写或重组正文：读取 [writing-and-evidence.md](references/writing-and-evidence.md)。
- 排版或视觉审查：读取 [design-system.md](references/design-system.md)。
- 使用 HTML 输出：再读取 [html-workflow.md](references/html-workflow.md)，按需使用配套样式、示例和渲染脚本。
- 查找设计来源、规范适用范围：读取 [sources-and-scope.md](references/sources-and-scope.md)。

仅润色文字时保留现有格式；仅审查时给出有依据的发现。不要为了使用本技能而把任务扩展成重新制作全部材料。

## 确定要求与证据

先确认读者、交付格式、篇幅和已有资料。接收方的明确格式及用户选择优先于模板默认值。资料足够时直接推进；缺少会改变结论的数据或必要格式时，指出具体缺口。

将正文中的主要结论对应到来源、数据或可说明的分析过程。区分观察结果、计算结果和解释；缺失的信息保持待核实状态。示例数据、过去项目的案例和附带模板中的陈述不能作为新报告的研究结果。

报告结构按问题选择。研究报告可展开方法、结果与讨论；方案报告可围绕需求、备选方案和验证计划；项目总结可围绕目标与完成证据。不要强制所有报告采用相同目录、固定页数或相同图表数量。

## 写作与数据表达

使用完整、清楚的句子说明对象、动作、条件与结果。结论力度与证据相称，保留具体贡献及其适用范围。减少空泛宣传、同义重复和反复辩解。

图表标注指标、单位、统计口径与来源。汇总数据应能回到分项记录；公式定义符号与分母。按材料需要选择平均方式、误差说明和图表类型。涉及新近规则或外部事实时核对对应的权威来源。

## 排版与导出

无指定模板时，使用配套的 A4 单栏风格：苹方优先、深蓝灰正文、清楚的标题层级、少量蓝绿色图形及三线表。具体尺寸见设计参考，可根据阅读场景统一调整。

表题置于表上方，图题置于图下方；图表与说明相邻。保留可编辑的表格、图形和正文源文件。复用演示材料中的图形时单独导出相关元素，并按报告阅读尺寸调整。

按任务选择 Markdown、HTML、DOCX 或 LaTeX。当前环境有适用的文档或 PDF 工具与操作规范时，按其要求处理文件；本技能提供内容与视觉判断，不依赖某个产品或模型。

PDF 优先保留可搜索文字。采用页面图像合成时说明检索限制，另附文字源文件。不要把使用某条渲染路径等同于满足接收方全部格式要求。

HTML 路径可使用 [report.css](assets/html/report.css)、[example.html](assets/html/example.html) 和 [render_html.py](scripts/render_html.py)。这些资源采用固定分页；增删内容后重新检查分页。脚本会生成页面预览和机械检查记录，检查通过后导出文字型 PDF。

## 交付前验收

检查最终导出文件的每一页，核对文字、表格、图形、图题、页码和分页。重新核对重要数据、引用及其来源。机械检查通过后，仍需实际查看页面；若当前环境无法完成视觉检查，应明确哪些检查尚未完成。

遵守接收方的署名与匿名要求，检查相应的文件名和元数据。默认保留合法来源归属，不主动抹去作者署名。

交付实际完成的文件与源材料入口，简要说明结果及必要的使用条件。未经用户要求，不额外发布文件、上传私人资料或更改其他项目配置。
