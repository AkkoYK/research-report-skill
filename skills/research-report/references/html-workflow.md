# HTML 排版与导出

## 使用范围

配套 HTML/CSS 用于固定分页的 A4 报告。每页包含 `.pdf-page`、`.page-content` 和 `.pdf-footer`，支持表格、图形和中文字体回退。它不是自动分页引擎；修改文字、字体或图表后应重新分配页面内容。

工作时复制样式与示例到本次报告目录，再编辑副本。不要把新项目内容写回已安装技能的资源目录。示例资料和数字均为虚构，正式报告需用真实材料替换。

## 选择制作工具

正文可从 Markdown 转成语义化 HTML，或直接编辑 HTML。保持标题、段落、表格和图形的结构，避免仅靠绝对定位拼文字。表格使用原生元素，图表保留源数据与可编辑版本。

如果交付要求是原生 DOCX，应在文档工具中实现同样的版式；如果已有指定 LaTeX 模板，按指定模板工作。无需先转成 HTML。

## 可选渲染脚本

在技能根目录执行以下命令。依赖只用于 HTML 渲染；编写和审阅正文不需要安装。

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r scripts/requirements.txt
python -m playwright install chromium
python scripts/render_html.py assets/html/example.html --output-dir build/example
```

Windows 可使用虚拟环境中的 `Scripts/python.exe` 执行同样的 Python 命令。脚本要求 Python 3.11 或以上；浏览器安装遵守当前环境的权限和网络要求。

有可用的本机 Chrome/Chromium 时，可通过 `--executable-path` 提供可执行文件路径。脚本不会替换系统设置或自动安装浏览器。

默认仅允许输入 HTML 所在目录中的本地资源，阻止网络请求，并禁用页面自己的 JavaScript。额外的本地资源目录通过 `--asset-root` 明确提供；无需访问远程账号或 API。需要交互脚本生成的图表应先导出成静态图形。

输出目录必须是新目录。脚本发现已有目录会退出，避免覆盖现有材料。每次修订可使用不同目录。

## 输出与检查

- `page-001.png` 等：按打印样式生成的每页预览。
- `layout-check.json`：内容边界、表格边框、图片加载、实际字体与浏览器版本。
- `report.pdf`：机械检查通过后导出的文字型 PDF。

导出 PDF 时，本地文件链接保留可见文字并移除文件路径跳转，避免把制作机器的绝对路径写入 PDF；源 HTML 不变，处理数量写入检查记录。需要对外可点击的引用时，在正文源文件中使用经核验的公开链接。

退出码 `0` 表示机械检查通过；`2` 表示布局或资源检查失败，保留预览与检查记录供修订；`1` 表示输入、依赖或渲染错误。失败时不应把不完整输出当成交付文件。

脚本检查文字或图形越界、缺失图片、三线表的基本边框以及被阻止的资源。它不证明表格数据正确、所有对象互不重叠，也不代替视觉检查。检查记录中的 `visual_review` 保持 `required`，由实际逐页检查完成验收。

## 最终验收

先查看全部预览，再用可用的 PDF 渲染工具检查实际 PDF。确认页面数量、实际纸张尺寸、文字搜索与复制、字体、图表、页码和链接。特别检查固定 HTML 页是否因打印分页又产生空白页或额外页。

PDF 可搜索不等于完全满足可访问性标准。需要 PDF/A、PDF/UA 或指定文档标准时，使用对应工具单独验证，并保留验证结果。

若只能导出页面图像，应交代文字检索限制并保留文字源文件。对外分享的文件按接收方要求检查署名和元数据。
